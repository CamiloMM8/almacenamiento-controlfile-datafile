Mapa del control file

Un tablespace es lógico y cada data file pertenece a uno solo. El control file guarda esa lista. El redo log queda al margen.

Lista cada data file.

Historial del control file

Archived logs y piezas de RMAN se reutilizan. CONTROL_FILE_RECORD_KEEP_TIME vale 7 días.

V$CONTROLFILE_RECORD_SECTION
TYPETipo de sección
ARCHIVED LOGReusable
BACKUP SETReusable
BACKUP PIECEReusable
DATAFILEFija
REDO LOGFija

CONTROL_FILE_RECORD_KEEP_TIME = 7. Un registro reusable con más de 7 días puede sobrescribirse; si ninguno cumple ese plazo, el control file crece.

Arranque del control file

Oracle sube la base en tres estados. Cada uno lee un archivo más. Baja para pasar al siguiente.

  1. NOMOUNT sin control file

    La instancia sube. El control file todavía no se lee. STARTUP NOMOUNT basta para crear un control file nuevo.

  2. MOUNT del control file

    ALTER DATABASE MOUNT abre cada control file de CONTROL_FILES. Si una ruta de la lista falta, la base no monta.

  3. OPEN de los data files

    ALTER DATABASE OPEN abre los data files y compara cada cabecera con el registro del control file.

Dudas del data file

No cubre el redo log ni una recuperación completa.

Ver la anatomía del data file

¿Monta si falta un control file de la lista?

No. Oracle exige cada ruta de CONTROL_FILES. La copia que queda sirve para reponer la dañada.

¿Un data file cabe en dos tablespaces?

No. Un data file pertenece a un solo tablespace. Un tablespace smallfile puede tener varios.

¿El tempfile sale en V$DATAFILE?

No. El tempfile se consulta en V$TEMPFILE y en DBA_TEMP_FILES.

¿Se borra el data file system01.dbf en caliente?

No. DROP DATAFILE solo vale si el data file no tiene extents. SYSTEM no admite OFFLINE.

Data file smallfile

Hasta 4194304 bloques. Con 8 KB, 32 GB.

Data file bigfile

Un solo data file. Con 8 KB, 32 TB. Con 32 KB, 128 TB.

Data file de undo

El tablespace undo usa un data file de verdad.

Tempfile y data file

Se consulta en V$TEMPFILE, no en V$DATAFILE.

Operaciones del data file

SYSTEM no admite OFFLINE. Las rutas son las del ejemplo ORCL.

ALTER TABLESPACE users ADD DATAFILE crea users02.dbf con AUTOEXTEND y un MAXSIZE.

DBA_DATA_FILES muestra el archivo nuevo en USERS.

Ver el contraste

ALTER DATABASE DATAFILE ... RESIZE cambia el tamaño del archivo que ya existe.

AUTOEXTEND ON NEXT sigue creciendo hasta MAXSIZE.

Volver a la cabecera

ALTER DATABASE MOVE DATAFILE mueve el archivo en línea. Existe desde 12c y vale en 19c.

Copias del control file

SHOW PARAMETER control_files lista las rutas. Oracle escribe en todas a la vez y exige cada una al montar.

  1. Graba la lista nuevaALTER SYSTEM SET control_files = ... SCOPE = SPFILE.
  2. Baja la baseSHUTDOWN IMMEDIATE.
  3. Copia el archivoCon el sistema operativo, de control01.ctl a la ruta nueva.
  4. Vuelve a subirSTARTUP lee las tres copias.

La copia binaria sale con BACKUP CONTROLFILE TO. El script de texto, con TO TRACE. Si una ruta de la lista falta, la base no monta.
